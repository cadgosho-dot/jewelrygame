==================================================
0. この引き継ぎの目的 / 最重要
==================================================

このファイルは、ここまで承認された「迷子犬・犬探し連続イベント」全体を
JEWELRY×JEWELRY本体へ実装するための引き継ぎデータ。

ユーザーから「全体を実装させましょう」と明示的な実装許可あり。
以後は本体実装へ進んでよい。

ただし、この実装は大掛かりなので以下を最優先する。

【最優先の作業手順】
・止まらないこと。
・無駄な再調査を繰り返さないこと。
・必要箇所だけ確認 → 修正 → 保存 → 次へ。
・GitHub main の VERSION / HEAD は実装開始時に1回だけ確認。
・同じ画像、同じCSS、同じGit履歴、同じ既存処理を理由なく何度も確認しない。
・一度に全部を巨大変更しない。
・作業ブランチ上で小さく保存しながら進め、最後は1つのPRとしてまとめる。
・今回と無関係な既存不具合は同時に修正しない。
・既存の正常機能、セーブ、画像、音声、UIを壊さない。

【モジュール方針】
・新規主要ロジックは js/events/ 配下へ独立モジュールとして実装する。
・app.js は呼び出し・接続に必要な最小限のみ。
・app.jsへ犬イベントの大量データ/状態遷移/抽選ロジックを直書きしない。
・既存イベントをこの作業に合わせて一斉移動・全面リファクタリングしない。

【UI】
・全場面「通常イベントUI」。
・通常イベントUIは固定仕様。
・クイズイベントUIへ影響させない。
・既存通常イベントUIのグローバルCSSを今回のために変更しない。
・必要な追加CSSは犬イベント固有のスコープ内に閉じる。
・セリフ・画像は以下の登録内容をそのまま使用し、勝手に書き換えない。
・○○○は実ゲームのプレイヤー名へ置換する既存方式に合わせる。

4. 犬探し周期 / 状態仕様
==================================================

【初回開始条件】
・「母親狼イベント」を完了済みであること。
・既存状態キーは wolfMotherButlerEvent。
・wolfMotherButlerEvent.completed === true を利用する。
・母親狼イベント終了から30日以上経過後。
・既存 wolfMotherButlerEvent には startedDay が保存されているため、
  まずはこれを母親イベントの当日基準として利用し、
  不要な新規セーブ項目を増やさない。
・条件達成後、店舗へ入った時に20%の確率で
  「狼少年・迷子犬イベント」が始まる。
・抽選に外れた場合は通常の店舗画面へ入り、
  次回店舗入場時に再び20%抽選する。

確定:
初回導入の発生確率は20%。

【導入完了後】
犬探し周期を active にする。

【途中イベントの抽選】
・対象の場所へ行った時、約50%ではなく「50%」で抽選。
・その場所の途中イベントをその周期でまだ完了していない場合だけ抽選。
・外れた場合は何も起きず、通常画面のまま。
・次回同じ場所へ行った時に再び50%抽選可能。
・一度その途中イベントを最後まで完了したら、その周期中は二度と発生しない。
・同じ場所へ何度行っても、完了済みなら抽選もしない。
・途中でイベント終了ボタン等により最後まで見なかった場合は「完了」にしない。
・カウントは日をまたいで保存する。

【犬発見条件】
・途中イベントを異なる5個、最後まで完了する。
・同一場所の重複は不可（そもそも周期中1回のみ）。
・途中イベント完了数は「完了済みIDの数」から導出するのが望ましい。
  countとseenを二重保持して不整合を作らない。
・5個目を見終えた瞬間には犬発見イベントを始めない。

【5個達成後】
・御徒町へ入った時に50%の確率で犬発見イベント発生。
・外れた場合、次回御徒町へ入った時に再び50%抽選。
・犬発見までは進行状態を保存。
・5個達成後は検索完了待ち状態として扱い、
  中途イベント数を5より増やさない実装にする。

【犬発見後】
・犬発見イベントを最後まで完了したら、その周期を終了。
・途中イベント完了済みIDをリセット。
・途中イベント完了数は0相当に戻る。
・犬発見待ち状態も解除。
・次の周期に備える。


【他イベントとの同時発生防止 / 優先順位】
・犬探しイベント系の抽選に当選した入場では、
  その入場中に他のランダムイベントを同時発生させない。
・犬探しイベントが実際に開始した場合は、その入場のイベント処理を占有する。
・犬探しイベント側の抽選が外れた場合は、
  既存の通常ランダムイベント抽選へ進んでよい。
・同一画面で複数イベントoverlayが重ならないよう、
  既存の running / overlay存在チェック等を利用して排他制御する。
・既存イベントの優先順位を無関係に全面変更しない。

【繰り返し】
・この一連のイベントは繰り返し可能。
・初回は「母親狼イベント終了から30日以上経過後」が入口。
・初回条件達成後、店舗入場時20%で導入イベント発生。
・犬発見イベント完了日を lastCompletedDay として保存。
・2周期目以降は、前回の犬発見イベント完了から180日以上経過後、
  店舗へ入った時に20%の確率で「狼少年・迷子犬イベント」が再発生。
・抽選に外れた場合は通常の店舗画面へ入り、
  次回店舗入場時に再び20%抽選する。
・新周期開始時に途中イベントseen状態、犬発見待ち状態、
  最終報酬受領状態などを新周期用に正しく初期化する。

確定:
2周期目以降は「前回犬発見から180日以上 + 店舗入場時20%」。

5. セーブ設計（推奨・最小限）
==================================================

既存 save 形式を大きく変えない。
event-state-helpers.js の patchEventState / eventRuntimeSnapshot 等を活用する。

推奨イベントキー:
dogSearchEvent
（最終名は既存命名規則に合わせてよいが、複数キーへ無駄に分散しない）

保存は最小限にする。

例:
events.dogSearchEvent = {
  active: true/false,
  introCompleted: true/false,
  seenEventIds: [...],
  finalActive: true/false,
  finalStage: "...",
  finalRewardGranted: true/false,
  lastCompletedDay: number
}

・lastCompletedDay は犬発見イベントを最後まで完了したゲーム日。
・2周期目以降は currentDay >= lastCompletedDay + 180 を再開条件に使う。
・途中イベント完了数は seenEventIds.length から導出。
・同一IDを二重登録しない。
・犬発見報酬の二重受け取りを防ぐため finalRewardGranted は保存する。
・犬発見イベント途中で再読込してもK18が二重付与されないこと。
・lastCompletedDay は次周期判定に必要になるため、犬発見イベント完了日に記録。
・不要な保存項目を増やさない。

6. 全イベント共通の効果音
==================================================

この連続イベント内の全イベントに効果音を付ける。

【通常タップ】
・各セリフをタップして進めるたびに、ゲーム内の通常タップ効果音。
・既存 playSfx('select') 相当を使用。
・「ん？」タップ、報酬タップ等も自然な既存効果音を使用。
・音量は既存イベントと同程度。

【犬発見時】
・犬「牧羊犬」が表示されたタイミングで、承認済み携帯確認版の
  「嬉しい効果音」を鳴らす。
・携帯確認 v5 では Web Audio による短い上昇チャイム。
・本番でも同じ印象・タイミングを維持。
・ユーザーから「作って」と明示許可済み。

【ラスト】
・最後の狼少年
  「ありがとうございました○○○さん！、、、、」
  をタップした瞬間、
  承認済み携帯確認版の「嬉しいラストシーンの効果音」を鳴らし、
  メイン画面へ戻る。
・携帯確認 v5 のタイミング・印象を維持。
